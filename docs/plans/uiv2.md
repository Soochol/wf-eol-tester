# PySide6 UI v2 디자인 적용 플랜 (현재 스타일 다듬기, A안)

- 작성일: 2026-11-19
- 이 문서는 승인 시점의 기록이며 구현 중 바뀐 것은 반영하지 않는다.

## 풀려는 문제

지금 화면(v1)은 기능은 다 있지만 장비 모니터(1280×1024)에서 투박하게 보인다. 사용자는 "UI를 훨씬 더 세련되게" 바꾸길 원했고, 밝은 스타일을 유지하며 다듬는 A안을 골라 v2 시안을 승인했다("좋아"). 실제 하드웨어 PC 화면을 보면 창이 1280×800으로 떠서 아래가 비고, IBM Plex 글꼴이 설치돼 있지 않아 기본 글꼴로 보인다.

## 확정된 결정 (사용자)

1. 시안은 캔버스 https://claude.ai/artifact/XGs6b1XLmSogFjqoazuRak 의 "v2" 줄(MainV2, ResultV2)이다. 색 토큰은 시안 값을 그대로 쓴다.
2. 대상 화면은 하드웨어 PC 모니터 1280×1024다. 이 크기에서 스크롤 없이 v2처럼 보여야 한다.
3. v2 변경점은 요청서의 9가지다. 헤더(로고 배지, 세그먼트 탭, 장치 칩), 작업 정보 카드(주 버튼, 중단 버튼, 안내 줄), 진행 상태(스테퍼, 진행 막대와 %, 상태 배지, 회전 아이콘), 로그(남색 콘솔, 레벨 배지, 세그먼트 필터, 빈 상태), 실시간 값 타일, 측정 결과(빈 상태, 채움 막대), 판정 완료 화면(그라데이션 배너, 표 머리글, 저장 파일·Teardown·다음 DUT 카드), 공통(배경 #EEF0F4, 카드 radius 14와 옅은 그림자), 글꼴 번들(OFL 라이선스 포함, QFontDatabase 등록)이다.
4. 설정 화면은 공통 요소(헤더, 카드, 버튼, 글꼴)만 v2 토큰에 맞춘다. 레이아웃은 다시 짜지 않는다.
5. 동작(러너, 진행 계산, 설정 모델, `eol_tester`)은 바꾸지 않는다.
6. 기존 UI 시험은 그대로 통과해야 하고 약하게 만들지 않는다. 1280×1024 offscreen 렌더 스크린샷(대기, 진행 중, PASS, FAIL)을 보고서에 붙인다.

## 스스로 정한 결정과 이유

1. **세 작업으로 나눈다.** `uiv2-shell`(테마 토큰·QSS·글꼴·아이콘·그림자 도우미·헤더·창 크기·화면 맞춤 시험) 뒤에 `uiv2-run`(실행 화면과 로그 패널)과 `uiv2-result`(판정 완료 화면)를 병렬로 둔다. 실행·판정 화면이 같은 토큰, 배지·막대 QSS, 아이콘, 그림자 도우미를 쓰므로 공통 부분을 먼저 병합해야 두 화면 작업이 같은 파일을 서로 고치지 않는다.
2. **기존 시험이 읽는 문자열과 접근자는 그대로 둔다.** `applied_text()`의 "적용된 변경 N개", 로그 `count_text()`의 "N줄 · 경고 M", `visible_lines()`의 "HH:MM:SS  LEVEL  메시지" 형식, `badge_texts()`의 "PASS/FAIL/판정 대기/미완료", 결과 `banner_summary`의 "N/M", `teardown_text()`의 "passed: 예", 객체 이름(`start-button`, `tab-0`, `device-robot` 등)과 `device_connected()`다. 시안 문구가 이것과 다르면 화면에는 시안 문구를 더하되 이 문자열을 지우지 않는다. 기존 시험 파일(`tests/ui/test_run_screen.py`, `test_settings_screen.py`, `test_window_teardown.py`)은 어느 작업의 `paths`에도 넣지 않아 고칠 수 없게 한다.
3. **측정 행은 예정 행을 미리 만들지 않는다.** 시안 진행 화면은 아직 안 한 온도를 "대기" 행으로 미리 보여 주지만, 지금 시험(`row_count`, `badge_texts`)이 "끝난 측정만 행이 된다"는 의미에 기대고 있다. 그래서 예정 수는 빈 상태 안내("측정 N회 예정")와 머리글의 "완료/전체" 숫자로만 보여 준다.
4. **창은 최대화로 띄운다.** 하드웨어 PC 캡처에서 창이 1280×800으로 떠 화면 아래가 비었다. `app.main`이 `showMaximized()`로 띄운다. 최대화한 창의 실제 작업 영역은 제목 표시줄과 작업 표시줄을 빼면 높이가 약 940px이므로, 화면 맞춤 시험은 중앙 위젯이 1280×940 안에 잘림 없이 들어가는지 확인한다. 스크린샷은 요청대로 창 1280×1024로 찍는다.
5. **입력칸 44px는 실행·판정 화면에만 쓴다.** 전역 `QLineEdit`/`QComboBox` 높이를 키우면 필드가 많은 설정 화면이 길어진다. 큰 입력칸은 속성(예: `size="lg"`)으로 고른다.
6. **그림자는 로그 카드에 걸지 않는다.** `QGraphicsDropShadowEffect`는 자식이 다시 그려질 때마다 카드 전체를 다시 그린다. 로그는 실행 중 계속 줄이 늘어서 비용이 크다. 로그 카드는 테두리만 쓴다.
7. **판정 화면의 중단·오류 배너 색.** 시안에는 PASS/FAIL만 있다. ERROR는 FAIL과 같은 빨강 그라데이션, ABORTED는 회색 그라데이션(#475467→#344054)으로 한다.
8. **글꼴은 7개 파일을 번들한다.** IBM Plex Sans KR Regular/Medium/SemiBold/Bold(시안이 400/500/600/700을 씀, 파일당 약 2.8MB)와 IBM Plex Mono Regular/Medium/SemiBold(파일당 약 0.14MB), 합계 약 11.8MB다. 출처는 google/fonts 저장소의 `ofl/ibmplexsanskr`, `ofl/ibmplexmono`이고 OFL.txt를 함께 넣는다. 저장소가 이만큼 커진다.
9. **아이콘은 시안의 SVG 경로를 그대로 쓴다.** 공통 아이콘 모듈 하나(`eol_ui/widgets/icons.py`)에 모아 두 화면 작업이 같이 쓴다. `PySide6.QtSvg`로 그린다.

## 작업

| 작업 | 내용 | 순서 | 방식과 이유 |
|---|---|---|---|
| `uiv2-shell` | 토큰·QSS v2, 글꼴 번들과 등록, 아이콘, 그림자 도우미, 헤더(로고·세그먼트 탭·장치 칩), 창 최대화, 1280 화면 맞춤·스크린샷 시험 | 먼저 | basic: 테마·문구·화면 조정이고 상태 저장·동시성이 없다 |
| `uiv2-run` | 실행 화면(작업 정보 카드, 스테퍼 진행 카드, 타일, 측정 목록), 로그 패널 | `uiv2-shell` 뒤 | basic: 화면 조정이고 러너·진행 계산은 그대로 쓴다 |
| `uiv2-result` | 판정 완료 화면(배너, 표, 저장 파일·Teardown·다음 DUT 카드) | `uiv2-shell` 뒤 | basic: 화면 조정이다 |

- `uiv2-run`과 `uiv2-result`는 병렬이다. 고치는 파일이 겹치지 않는다(`eol_ui/pages/run/**`+`eol_ui/widgets/log_panel.py` 대 `eol_ui/pages/result/**`).
- 두 화면 작업이 `uiv2-shell` 뒤인 이유: 둘 다 그 작업이 만드는 토큰, 배지·막대 QSS, 아이콘, 그림자 도우미, 화면 맞춤 시험을 쓴다.

## 범위 밖

- 러너, 진행 계산(`eol_ui/progress.py`), 설정 모델(`eol_ui/settings/**`), `eol_tester`의 변경.
- 설정 화면(테스트 파라미터, 하드웨어 연결)의 레이아웃 재설계.
- 측정 목록에 예정 행을 미리 만드는 것(결정 3).
- 실장비(Windows)에서의 확인. 시험과 스크린샷은 Linux offscreen으로만 한다. 하드웨어 PC에서 보는 것은 병합 뒤 사용자가 한다.
- 패키징(PyInstaller 등)에 글꼴을 넣는 일.

## 사용자가 정해야 하는 결정

- 이 플랜에 검증을 약하게 하는 작업(검증 단계 삭제, 시간 제한 증가, `paths` 축소)은 없다.
- 글꼴 약 11.8MB를 git에 그대로 커밋한다(결정 8). LFS를 쓰거나 굵기를 줄이고 싶으면 승인 전에 알려 달라.
- 창을 최대화로 띄우는 것(결정 4)은 시안에 없던 동작 변경이다. 원치 않으면 알려 달라.
